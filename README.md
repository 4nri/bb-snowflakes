# Снег на макетах BetBoom

[Открыть демо](https://4nri.github.io/bb-snowflakes/) · [Макеты Figma](https://www.figma.com/design/mZPIQ2poXiuRzyO4JU2nPS/BB---2026?node-id=7596-3042)

Два исходных макета 393 × 852 рядом, анимированный снег поверх каждого и общая панель настройки. Макеты экспортированы из Figma в PNG; интерфейс акции в стенде статичен.

После дизайн-аудита стенд пересобран: светлая область сравнения, инспектор справа, закреплённые действия передачи настроек. На телефоне предпросмотр и настройки находятся в одном viewport, прокручиваются только параметры. [Аудит, решения и проверка](docs/design-audit.md).

## Возможности

- Количество, размер, разброс размеров и непрозрачность простых круглых точек. Крупные движутся быстрее мелких.
- Скорость падения, ветер в обе стороны, покачивание.
- Три пресета: лёгкий снег, снегопад, метель.
- Снег по всему контенту или только на иллюстрации. Шапка и системные панели исключены.
- Пауза, выключение, масштаб, полноэкранный просмотр. Целевая частота 60 FPS.
- Экспорт/импорт JSON, ссылка с текущими настройками, сохранение в браузере.
- На узких экранах два макета остаются видимыми над настройками. При ручном масштабе прокручивается только предпросмотр.

На стартовом макете уже нарисованы снежинки. Они входят в исходный PNG и остаются видны при выключении анимации. Для чистого сравнения эффекта используйте правый макет или замените левый экспортом без статичного снега.

## Запуск

Нужен Node.js 20 или новее. Установка пакетов и сборка не требуются.

```sh
npm run dev
# http://127.0.0.1:4173
npm test
npm run check
```

Для размещения на любом статическом хостинге достаточно `index.html`, `styles.css`, `src/`, `assets/`. GitHub Pages публикует корень ветки `main`.

## Интеграция

Скопируйте только **`src/snow.js`** в свой проект. Стенд, PNG, панель и другие файлы модулю не нужны. Runtime-зависимостей нет.

```html
<div class="scene" id="scene">
  <!-- Контент вашего приложения -->
</div>
<style>
  .scene { position: relative; overflow: hidden; }
</style>
<script type="module">
  import { Snow } from './snow.js';

  const host = document.querySelector('#scene');
  const snow = new Snow(host, {
    count: 40,
    size: 2,
    sizeVariation: 0.8,
    speed: 28,
    wind: 6,
    sway: 10,
    opacity: 0.65,
    enabled: true
  }, { referenceWidth: 393 });

  snow.update({ wind: -20 });
  // snow.setClip(98, 818); // верхняя и нижняя границы в координатах макета
  // snow.pause();
  // snow.play(); // учитывает prefers-reduced-motion
  // snow.destroy(); // вызывайте при размонтировании
</script>
```

`referenceWidth` задаёт ширину системы координат, по умолчанию 393. Размеры и скорость сохраняют пропорции при масштабировании контейнера. Для другого макета передайте его исходную ширину. Высота берётся из пропорций контейнера. Размер контейнера должен быть задан контентом или CSS.

Изменения настроек активной анимации применяются на следующем запланированном кадре. Для приостановленного эффекта обновление рисуется сразу.

В стенде автосохранение после жеста или 180 мс покоя выполняется в свободное время браузера. При уходе со страницы ожидающая запись завершается сразу. При перезагрузке восстанавливается последнее сохранённое состояние, при открытии новой ссылки приоритет имеют её параметры.

Canvas располагается поверх контента, не перехватывает клики и скрыт от скринридера. При сложной структуре слоёв задайте своему контейнеру `isolation: isolate` и нужный `z-index` для canvas.

### Настройки

| Ключ | Значение по умолчанию | Диапазон / смысл |
| --- | --- | --- |
| `count` | 40 | 0–200 частиц на один контейнер, включая частицы вне области отсечения |
| `size` | 2 | 0.5–6, максимальный радиус в px |
| `sizeVariation` | 0.8 | 0–1, разброс размеров и скоростей. При 0 все одинаковые, при 1 радиусы и скорости от 25% до 100% максимума |
| `speed` | 28 | 0–160 px/с, базовая скорость, зависит от глубины |
| `wind` | 6 | −100…100 px/с, минус влево |
| `sway` | 10 | 0–60 px, амплитуда покачивания |
| `opacity` | 0.65 | 0–1, максимальная непрозрачность |
| `enabled` | true | Выключение скрывает анимацию |

`normalize()` проверяет и ограничивает внешние значения. Неизвестные поля игнорируются, некорректные значения заменяются стандартными.

Параллакс создаётся разной скоростью: крупные частицы воспринимаются ближе и движутся быстрее, мелкие остаются дальше и движутся медленнее. `sizeVariation` применяется к радиусу, падению, ветру и покачиванию. Случайная глубина задаётся один раз при создании; изменение ползунка сохраняет позиции и распределение частиц. Коэффициенты пересчитываются только при изменении разброса. Дополнительных слоёв и фильтров нет. Старые JSON и ссылки без этого поля загружаются со значением 0.8.

### Использование JSON из стенда

Файл содержит `{ version, settings, area }`. Передайте `settings` в конструктор. `area` относится к двум макетам стенда; для своего интерфейса задайте границы через `setClip(top, bottom)`.

```js
const config = await fetch('./bb-snow-settings.json').then(r => r.json());
const snow = new Snow(host, config.settings, { referenceWidth: 393 });
```

### Движение и ресурсы

Один общий `requestAnimationFrame` для всех экземпляров. На каждом экране один Canvas. Все точки рисуются одним общим путём и одним вызовом `fill()`. Текстур, изображений частиц, размытия и покадровых CSS-фильтров нет. Буфер имеет DPR 1, в том числе на Retina: декоративный слой не требует увеличения числа пикселей в 4–9 раз. По умолчанию 40 точек на экран, 80 на весь стенд. При частоте дисплея около 60 Hz модуль рисует каждый доступный кадр. На дисплеях 75/90/120/144 Hz ограничивает отрисовку примерно 60 кадрами в секунду. Это сохраняет плавность без редких искусственных пропусков из-за расхождения часов браузера и ограничителя.

Модуль останавливает кадры, если вкладка скрыта, контейнер вне видимой области, включена пауза, эффект выключен или количество равно нулю. Движение рассчитывается по времени, а шаг после задержки ограничен 50 мс. Поэтому возвращение во вкладку не вызывает скачка снега.

`prefers-reduced-motion: reduce` останавливает модуль по умолчанию. После явного действия пользователя можно вызвать `snow.play({ ignoreReducedMotion: true })`. В стенде это кнопка «Запустить».

FPS в нижней строке измеряется по фактическим кадрам одного активного экрана. Рядом показано время расчёта и отрисовки одного экрана (95-й процентиль последних 240 замеров обоих экранов). Замеры подключены только в стенде через необязательный `onFrame` в options; самостоятельный модуль по умолчанию их не собирает. Это диагностическое значение, а не гарантия скорости на любом устройстве. Размер модуля и результаты проверок: [docs/status.md](docs/status.md). Подробная проверка CPU ×4/×6/×10: [отчёт о производительности](docs/performance.md).

После добавления параллакса отдельно проверены максимальный радиус 6 px, 200/400 частиц и изменение разброса: [повторная проверка CPU ×6/×10](docs/performance-parallax.md).

## Повторить замеры CPU

Нужны установленный Google Chrome и Playwright как инструмент проверки. Он не входит в код, который загружает посетитель.

```sh
npm install --no-save --package-lock=false playwright
npm run dev
# В другом терминале:
npm run perf
```

Результат записывается в `output/playwright/cpu-baseline.json`, после каждого сценария. Браузер запускается в отдельном временном профиле. Длительность по умолчанию 8 секунд на сценарий после 2 секунд прогрева; вся матрица включает 30 сценариев. Для длительной проверки используйте файл конфигурации из [docs/performance-long-options.json](docs/performance-long-options.json):

```sh
PERF_OPTIONS_FILE=docs/performance-long-options.json PERF_OUTPUT=output/playwright/cpu-long.json npm run perf
```

Замер фиксирует фактические команды отрисовки Canvas и отдельный кадровый цикл браузера. CPU замедляется через `Emulation.setCPUThrottlingRate`, а не через искусственную задержку анимации. Подробные границы метода указаны в отчёте.

Проверка завершения жестов и сохранения настроек: `PERF_OPTIONS_FILE=docs/performance-bursts-options.json PERF_OUTPUT=output/playwright/cpu-bursts.json npm run perf`.

Проверка параллакса: `PERF_OPTIONS_FILE=docs/performance-parallax-options.json PERF_OUTPUT=output/playwright/cpu-parallax.json npm run perf`. Длинные прогоны: `PERF_OPTIONS_FILE=docs/performance-parallax-long-options.json PERF_OUTPUT=output/playwright/cpu-parallax-long.json npm run perf`. Проверка нового ползунка, JSON, ссылок и мобильной панели: `npm run smoke:parallax`.

Проверка интерфейса после дизайн-аудита: `npm run smoke:design`. Повтор CPU ×10: `PERF_OPTIONS_FILE=docs/performance-design-options.json PERF_OUTPUT=output/playwright/cpu-design.json npm run perf`.
