# Размытие снега: проверка производительности

22 октября 2026 года. В финальной версии 23 из 23 сценариев прошли без интервалов >25 мс в независимом кадровом цикле и отрисовке эффекта, без пропущенных callback. Полные результаты, включая отклонения, сохранены ниже. Эмуляция CPU не заменяет проверку физического телефона.

## Что изменилось

- Сила размытия задаётся параметром blur 0–1, стандартное значение 0.4. При 0 используется прежняя общая заливка чётких точек.
- Средний план остаётся резким; дальние точки мягче, ближние сильнее. Случайная глубина и позиции сохраняются при настройке.
- Восемь радиальных масок мягкого круга генерируются один раз в общем атласе 64 × 512 px. Мягкий край формируется заранее по радиальному профилю; в каждом кадре используются готовые маски. Минимальная ненулевая мягкость округляется к первому уровню, чтобы при стандартном разбросе дальний план тоже имел мягкий край.
- Кэш составляет 128 КиБ RGBA без служебных расходов браузера/GPU. На каждый макет остаётся один видимый Canvas с DPR 1. Новых сетевых ресурсов нет. Радиусы и номера масок пересчитываются при настройке, а не на каждом кадре.
- Модуль: 9284 байт исходника, 3405 байт gzip. Ранее 7401 / 2657 байт. Копирование мягких частиц и прозрачность добавляют работу; размытие не считается бесплатным.

## Условия

Chrome 156.0.8078.48, headless; Apple M2 Ultra, arm64. CPU ×6/×10 через CDP Emulation.setCPUThrottlingRate. Контрольная целочисленная работа подтверждает замедление: ×1: 3,70 мс; ×4: 16,40 мс; ×6: 25,20 мс; ×10: 42,00 мс; ×1: 3,60 мс.

Сравнение до изменения: commit 4aa612f; SHA-256 snow.js 70bb86e349114682cb9a6418b0518b3770694358c77306b5eaf0597da8dba1ce. Финальный SHA-256: f3264de4b71134573c565d813639eb724f3cebf1b39c35eef48bb49e7ed74ee6.

Короткие сценарии: 15 × 15 с, длительные: 8 × 30 с; перед каждым 2 с прогрева. В модуле Canvas занимает 393 × 852 при viewport DPR 3. Стенд 1280 × 900 содержит два макета; отдельно проверен мобильный вид 393 × 852. Все Canvas используют DPR 1. Проверены максимальный радиус 6 px, размытие 0/40/100%, разброс 0/1, 80/400 частиц. При разбросе 0 все точки близкие и максимально мягкие, что проверяет вариант без резких точек.

Жесты: input 10 раз в секунду, по 1 с движения и 0.5 с паузы, change после отпускания. Сценарий blur начинается с 0, поэтому включает первое создание кэша во время измерения. Время input/change сохранено в данных.

Независимый requestAnimationFrame фиксирует интервалы браузера; clearRect видимых Canvas фиксирует реальные команды отрисовки. Считаются средний FPS, минимум в окне 1 с с шагом 100 мс, p95/p99/максимум интервала, паузы >25/>50 мс, пропущенные callback, long tasks. CPU p95 включает расчёт и отправку Canvas-команд всех активных экранов за callback, вместе с обёрткой измерений. GPU-время, физическая презентация пикселей, температура и энергопотребление не измеряются. Минимум 59 в окне сам по себе не означает потерю кадра: при 59.94 Hz часть секунд содержит 59 событий; оценка опирается также на интервалы.

## Отклонение в первом прототипе

На CPU ×6, 80 частицах и blur 0.4 была пауза 133,20 мс. В том же прогоне максимальная работа callback 2,00 мс, long tasks 0, пропущенных callback 0. Причина паузы не установлена. Прототип затем изменён: минимальная мягкость дальнего плана больше не округляется к нулю. Полная матрица повторена на окончательном коде. Нельзя приписывать устранение паузы этому изменению. Исходные данные прототипа не удалены: [performance-blur-prototype-data.json](performance-blur-prototype-data.json).

## Воспроизведение и предел вывода

Финальная матрица: PERF_OPTIONS_FILE=docs/performance-blur-options.json PERF_OUTPUT=output/playwright/cpu-blur.json npm run perf. Длинные повторы: PERF_OPTIONS_FILE=docs/performance-blur-long-options.json PERF_OUTPUT=output/playwright/cpu-blur-long.json npm run perf. Сравнение до изменения использует копию commit 4aa612f в output/blur-baseline и docs/performance-blur-baseline-options.json. Общий отчёт собирает node scripts/summarize-blur.mjs.

При этой CPU-эмуляции подтверждено сохранение ровного кадрового интервала около 60 FPS на всех проверенных нагрузках финальной версии. Это не гарантия для всех слабых телефонов: CPU throttling не воспроизводит их GPU, нагрев и энергосбережение. Полные данные: [performance-blur-data.json](performance-blur-data.json). Параметры всех сценариев проверяются перед началом измерений.
