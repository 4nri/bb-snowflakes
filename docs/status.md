## Продолжение: замедление CPU

CPU throttling ×4, ×6 и ×10 с контролем ×1 завершён. Результаты и границы вывода приведены ниже и в docs/performance.md.

## Результаты CPU throttling

- Исправлен редкий искусственный пропуск кадра в ограничителе около 60 Hz.
- Оптимизированы контролы: обновляется только изменённый параметр, Canvas рисует на запланированном кадре; настройки сохраняются после жеста либо через 180 мс покоя.
- 30 сценариев по 8 секунд и 5 сценариев по 30 секунд. Все 28 сценариев со снегом прошли без пауз >25 мс, остальные 7 служили контролем без снега.
- CPU ×4/×6/×10: мобильный модуль до 200 точек; CPU ×10: стенд с 400 точками, непрерывное изменение и сохранение настроек. Минимум 60 кадров в секундном окне, максимальный интервал около 16.8 мс в итоговых прогонах.
- CPU p95 при ×10: 0.6 мс для мобильного модуля со 110 точками; 1.2 мс для двух экранов с 400 точками; 1.5 мс для двух экранов с настройкой и сохранением. Это время CPU, не GPU.
- Контрольная вычислительная задача: примерно 3.8 мс при ×1 и 42.0 мс при ×10, замедление подтверждено.
- Проверки контролов после оптимизации: сохранение JSON и ссылки, нулевое количество, обновление во время паузы.
- Отчёт: docs/performance.md. Исходные результаты: docs/performance-data.json. Скрипт повторного запуска: npm run perf.
- Физический слабый телефон не проверялся. Эти данные подтверждают результат CPU-эмуляции на Apple M2 Ultra, Chrome 156, а не гарантируют 60 FPS на любом устройстве.

## Сравнение старого проекта

Найден 4nri/bb_snowflakes, master c492fa2f979a01b5aea95fe28f821f46827b445e (25.11.2025). Один index.html, три Canvas, Float32Array, пакетная отрисовка по слоям, передний слой blur(2px), 3200 частиц.

- Сравнение завершено: 26 сценариев по 8 секунд и 5 по 20 секунд, CPU ×1/×6/×10.
- На стандартных настройках, с одинаковым фоном и без панелей, CPU ×10: среднее CPU-время 4.97 → 0.18 мс, p95 6.0 → 0.9 мс. Основное отличие нагрузки: 3200 → 40 частиц, 3 → 1 Canvas.
- При одинаковых 200 точках без размытия: 0.221 и 0.217 мс, разница около 2% на фоне разброса. Преимущество вычислительного цикла новой версии не подтверждено.
- Скрытие только старой панели: 55.6 → 58.9 FPS, пауз >25 мс 78 → 18 в 20-секундных прогонах. Точная стоимость панели требует дополнительных повторений.
- Новый модуль больше старого inline-JS в gzip: 2517 против 1945 байт. У него больше возможностей управления и остановки эффекта.
- Отчёт: [legacy-comparison.md](legacy-comparison.md), исходные данные: [legacy-comparison-data.json](legacy-comparison-data.json). Сценарий повторения: `npm run compare:legacy`.
- Код обеих анимаций при сравнении сохранён без изменений. CPU-эмуляция не заменяет проверку физического телефона и слабого GPU.

## Параллакс и разброс размеров

Реализовано: `sizeVariation` управляет разбросом радиусов и связанных скоростей; 0 означает одинаковые точки, 1 даёт диапазон 1:4. По умолчанию 0.8; пресеты снегопада и метели используют 0.9 и 1. Случайная глубина фиксируется при создании, коэффициент движения обновляется только при изменении настройки.

- `npm test`: 11 проверок успешно. Подтверждены скорость по глубине, радиусы 1:4, одинаковые точки при нулевом разбросе, сохранение позиций и распределения при настройке.
- `npm run check`: успешно.
- Браузер: ползунок и клавиатура, изменение на паузе, JSON экспорт/импорт, ссылка и localStorage, старые настройки без нового поля, пресеты и сброс, мобильная ширина 393 px. Ошибок консоли нет.
- На паузе при максимальном радиусе 2 px измерены реальные радиусы 0.519–1.982 px; возврат ползунка к прежнему значению восстановил то же распределение.
- CPU ×6/×10, 8 сценариев по 10 секунд: без пауз >25 мс, в том числе при максимальном радиусе 6 px и 400 частицах суммарно.
- В длинных прогонах обнаружены редкие паузы 33 мс при окончании жеста. Они совпали с сохранением и обновлением ссылки; повторились также на контроле ветра. Автосохранение перенесено в requestIdleCallback с резервной отложенной задачей и сбросом записи на pagehide.
- Три повтора после этой правки по 30 секунд при CPU ×10, 400 частицах и радиусе до 6 px: минимум 60 кадров в секундном окне, максимальный интервал около 16.8 мс, CPU p95 общего callback около 1.3 мс, без пауз >25 мс.
- Проверка немедленной перезагрузки выявила приоритет устаревшего hash перед последним состоянием. При reload теперь используется сохранённое состояние; новая входящая ссылка по-прежнему задаёт параметры. Проверены сохранение на pagehide и браузер без requestIdleCallback.
- Дополнительный 30-секундный контроль итоговой версии: 1799 кадров, одна пауза 33.3 мс в независимом кадровом цикле браузера, без пропущенных callback эффекта. Ближайшее событие ползунка было за 242 мс до паузы; её причина не установлена. Строгие 60 FPS во всех стресс-прогонах не подтверждены. Полные исходные результаты сохранены.
- Всего 17 сценариев: восемь по 10 секунд и девять по 30 секунд. Отчёт и данные: docs/performance-parallax.md, docs/performance-parallax-data.json. Далее: публикация.
